# 02: §9.11 双版本回归只验了单向（反向未验）

**What to build:** SPEC §9.11 要求「同一份源码，用**两个 emsdk 版本**各编一次，断言两个
产物都能被同一宿主 dlopen」。本仓目前只验了**单向**：6.0.12 编的 `.oct` → 5.0.7 宿主 ✔。
**反向（5.0.7 编的 `.oct` → 6.0.12 宿主）从未验过。**

**Blocked by:** 一个 emsdk 5.0.7 的工具链（本仓只装了 6.0.12）。

**Status:** ready-for-agent

**Settling:** 用 5.0.7 编的 side module 装进 6.0.12 宿主 ⇒ `node host.js`（宿主 6.0.12、side 5.0.7）—— rc=0 且打出 `ALL PASS` ⇒ 双向都通，「契约相等即可跨版本」无方向性（结案）；rc≠0（`LinkError` / 运行期炸）⇒ 该判据**有方向性**，SPEC §8 措辞与 STATE.md 那句须改成带方向的说法后结案。

## 为什么留着不删

STATE.md 现在写的是「按 SPEC §8『契约而非版本号』判定，两者不冲突」——
这个结论**只被单向证据支持**。契约判据若真有方向性（旧编译器产物装不进新宿主），
那 STATE.md 那句话就是**过强的活状态断言**，必须改成带方向的说法。

## 复跑方式（需要 5.0.7 工具链）

```sh
# 装第二个工具链（约 300 MB，不入库）
toolchain/emsdk/emsdk install 5.0.7
# 用它编 side module（同一套 SPEC §4.1/4.2 命令，只换 $BIN/$SR）
# 然后装进 6.0.12 宿主：
#   把产物放到 m0/build-wasm32/ 下当 minifn.so，跑 node host.js
```

M0 已经把这个流程脚本化了：`m0/run-m0.sh` 的 `[1]`/`[2]` 步换成 5.0.7 的二进制即可。
