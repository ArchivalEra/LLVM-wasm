# 02: §9.11 双版本回归只验了单向（反向未验）

**What to build:** SPEC §9.11 要求「同一份源码，用**两个 emsdk 版本**各编一次，断言两个
产物都能被同一宿主 dlopen」。本仓目前只验了**单向**：6.0.12 编的 `.oct` → 5.0.7 宿主 ✔。
**反向（5.0.7 编的 `.oct` → 6.0.12 宿主）从未验过。**

**Blocked by:** 一个 emsdk 5.0.7 的工具链（本仓只装了 6.0.12）。

**Status:** wontfix

> wontfix 的理由：下游 2026-10-11 全面切 6.0.12 并发运，5.0.7 轴整体退役（详见 Settling）。

**Settling:** ⚠️ **本单以 wontfix 结案（2026-10-17，用户点令：5.0.7 一切不碰）** ⇒
复跑判据（对后人）：`python3 zreflect/facts.py --get emcc_version` 若为 `6.0.12` 且
下游 STATE 记录 6.0.12 已发运 ⇒ 本单维持 wontfix（结案成立）；若哪天下游回退 5.0.7
（rc≠0 的那个世界回来了）⇒ 本单复活为 ready-for-agent。正文：
验证目标「5.0.7 → 6.0.12 方向」的前提是**下游还在 5.0.7**——而下游已于 2026-10-11
**三线全面切到 emsdk 6.0.12 并发运 8761**（其 STATE：`emsdk 6.0.12 已发运 8761`）。
5.0.7 轴已从生态**整体退役**，反向验证失去意义：不存在「会用 5.0.7 产物接 6.0.12 宿主」的
真实场景 ⇒ 不是「验了所以知道」，是「**问题问的那个世界不存在了**」。
已验的**单向**证据（6.0.12 编的 `.oct` → 5.0.7 宿主，M0/M1 期实测）**留档**：
它当时支持了 SPEC §8「契约相等而非版本串相等」的判定，且那个判定现在被同版本现实
覆盖（工具链与宿主同为 6.0.12）。**同版本端到端**已由
`driver/acceptance-*.mjs` + `release/check-wasm64-e2e.sh`（产物进真 6.0.12 宿主 dlopen，
12 PASS）持续复跑——那是现在唯一有意义的轴。

## 为什么留着不删

STATE.md 现在写的是「按 SPEC §8『契约而非版本号』判定，两者不冲突」——
这个结论**只被单向证据支持**。契约判据若真有方向性（旧编译器产物装不进新宿主），
那 STATE.md 那句话就是**过强的活状态断言**，必须改成带方向的说法。
